Customer 360 — third Stage A proof page, findings before touching code

Unlike Dashboard (needed a real IA merge) and Delivery (had two real illegible-dark-mode bugs), reading through Customer 360's named components — CustomerHero, StickyStatsRail, CustomerTabs, and the right-rail cards (AccountSnapshot, K2MetricsCard, ContactsCard, EventsTasksCard, MetadataCard) — turned up a page that's already in good shape:

What's already correct, no change needed

  • CustomerHero sits on --card, which the foundation-phase commit already repointed to --surface-1 (#262626) — it inherited the new palette for free.
  • AccountSnapshot / K2MetricsCard use the app's own glass-card utility, which already has a complete, correct .dark treatment (translucent surface, proper dark:text-emerald-400-style tone colors on every status indicator).
  • ContactsCard, EventsTasksCard, MetadataCard, and NpsTrend are built on Kognitos Lattice's own Card/ ChartContainer components — a separate design system with its own complete, independent dark theme (node_modules/@kognitos/lattice/dist/theme.css). The foundation-phase commit already flipped LatticeThemeProvider's default to dark, so these inherited a proper dark palette automatically, with no styling work of ours involved.
  • CustomerTabs' active-tab pill already uses the accent yellow consistently, same as Delivery's tab bar.

One real bug found — same class as Delivery's

_cards/arr-trend.tsx (the Overview tab's contract-ARR chart, visible by default) has its own third copy of the useChartTheme() hook with the same stale constants already fixed twice elsewhere (#71717a axis, #18181b tooltip bg, #f4f4f5 text) — retuning to --foreground-muted / --surface-1 / --foreground for consistency with the Trends tab and Delivery's Q-on-Q charts.

Recommendation: narrower scope than originally planned

The plan said "cards move to --surface-1 backgrounds with the new radius" for this page. Having now read the actual components, I don't think that's the right call: this single page already mixes the app's own glass-card system with Lattice's Card system, and both already render correctly in dark mode via their own complete theming. Converting just AccountSnapshot/K2MetricsCard to flat --surface-1 while ContactsCard/EventsTasksCard/MetadataCard stay on Lattice's own dark palette would leave the right rail with three visually distinct card treatments instead of two — more inconsistent, not less, and for no correctness gain (nothing here is actually broken).

Proposing: fix the one genuine bug (ArrTrend's chart chrome) and leave everything else as-is. A full glass → flat-surface unification across the whole customer page (including Lattice's cards) is a bigger, separate design decision — reasonable to fold into Stage B once more of the app has moved to the flat-surface system and there's a fuller picture of which convention should win app-wide.

Reply "yes" to go with the narrower scope above, or tell me to proceed with the full flat-surface conversion instead.
